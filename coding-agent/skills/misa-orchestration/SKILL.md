# モデルオーケストレーション（複数フェーズ実装の既定）

複数フェーズ・複数ファイルにまたがる実装タスクでは、1つのモデルで全部やらず、
次の分担を既定とする。

## 分担

- **指揮役（このセッションの上位モデル）**: 計画立案・フェーズ分割・各フェーズの仕様書き・
  成果物のレビュー・検証・コミットを担当する。難易度が最も高いフェーズ
  （データ互換・コアロジック・アーキテクチャ変更）は指揮役が自分で実装してよい
- **作業役（Agentツールのサブエージェント。`model` パラメータで指定）**:
  - 通常の実装・リファクタ・UI構築: 利用可能な中で実装能力の高い作業モデル
  - 機械的な作業（メタデータ・ドキュメント更新・定型コピー・一括置換・テスト雛形）:
    コスト効率のよい軽量モデル
  - ごく単純な探索・収集・整形: 利用可能な最軽量モデル
  - モデル名は固定せず、委譲時点で利用可能な選択肢と能力を確認して割り当てる

## 運用ルール

- サブエージェントには「対象ファイル・従うべきリポジトリ規約・検証手順・コミット禁止」を
  明記した自己完結の指示を渡す（サブエージェントは会話の文脈を持たないため）
- 並行実行は、触るファイルが重ならないフェーズ同士だけ。重なる場合は直列にする
- 指揮役は各フェーズの diff を必ずレビューし、検証（テスト・lint・プロジェクト固有のチェック）を
  通してからコミットする。サブエージェントの報告を鵜呑みにしない
- 迷ったら上位モデルに倒す。下位モデルへの委任は、機械的でコスト削減が明確な作業に限る
- 委譲はタスクの規模や処理量ではなく、難易度・独立性・必要な判断の多さで決める。
  大規模・大量という理由だけで下位モデルへ逃がさない

## Codex での読み替え

Codex には Claude Code の Agent ツール（`model` パラメータ付きサブエージェント）が
ないため、分担の考え方と運用ルールはそのままに、実現手段だけ次のように読み替える。

- **指揮役**: 対話セッションそのもの。reasoning effort を `high` 以上にして、計画・仕様・
  レビュー・検証・コミットを担当する
- **作業役**: `codex exec -m <model> "<自己完結の指示>"` で非対話セッションに切り出す
  - 通常の実装・リファクタ・UI構築: 既定モデル（`~/.codex/config.toml` の `model`）を
    effort `medium`〜`high` で
  - 機械的な作業（メタデータ・ドキュメント更新・定型コピー・一括置換・テスト雛形）: 軽量モデル
    または effort `low`
  - モデル名は世代交代が速いので固定で覚えない。`~/.codex/models_cache.json` か `/model` で
    そのとき利用可能なものを確認してから選ぶ
- 単一セッションで済ませたい大型タスクは、委譲を自動で行う effort（`ultra`）を使う手もある。
  その場合も diff のレビューと検証は指揮役の責任として省略しない

## GitHub Copilot CLI への委譲

GitHub Copilot CLI は、指揮役側のモデル利用量を節約するための実装ワーカーとして使う。
特定のプラン、モデル名、固定の性能序列を前提にせず、委譲時点で指揮役側と Copilot CLI の
それぞれで利用可能なモデルの能力を確認する。モデル能力が結果を左右する仕事は、その仕事に
必要な推論・実装能力を満たす上位モデルが直接担当する。Copilot CLI には、利用可能なモデルで
品質を担保でき、明確かつ独立して完結する仕事を割り当てる。

### 指揮役が直接担当する仕事

- 難しい新機能や中核機能の実装
- 大規模リファクタリング
- 設計・アーキテクチャ判断
- 曖昧な要件の整理と実装方針の決定
- 複数領域にまたがり、途中で高い判断力を要する変更

### Copilot CLI に委譲してよい仕事

- lint・format・定型修正
- テストの追加・修正
- 仕様が明確で、独立して完結する実装
- Issue 単位で完結し、受け入れ条件が明確な実装
- 一括置換など、大量だが単純な変更

Copilot CLI へは、可能な限り「調査 → 実装 → テスト → 結果要約」まで完結する単位で渡す。
対象範囲、仕様、受け入れ条件、検証手順、コミット禁止を指示に含め、指揮役は成果物のレビューと
統合判断に集中する。指揮役と Copilot CLI の双方が同じコードベースを全面的に解析するような
重複を避け、必要な文脈と担当範囲だけをワーカーへ渡す。
