# TTS ナレーション制作

環境・辞書のバックアップ・Qwen3-TTS は `~/dotfiles-mac/tts/README.md` を参照する。
日本語は AivisSpeech のローカル API（既定 `http://127.0.0.1:10101`）を使う。
ここで示す話速・タイミング・整音値は過去の制作で使った初期値であり、話者・原稿・用途に合わせて調整する。

## 進め方

1. 用途、原稿、話者、尺を既存の指示・素材から確認する。未指定の細部は妥当な初期値で進める。
2. `/speakers` で利用可能なスタイル ID を確認する。原稿を1行1発話にし、固有名詞と修正対象を
   `/audio_query` で調べる。カナ、アクセント核、句境界、`pause_mora` を根拠に修正する。
3. 音声を生成し、実ファイルの長さとピークを測る。動画用ならシーンの尺に合わせて原稿・間を調整する。
4. 誤読が明確なら修正して進める。自然さやアクセントに複数の有力候補が残る場合だけ比較音声を作る。
   試聴していない音声を「自然」「聞き取りやすい」と断言せず、機械的に確認したことと分けて伝える。
5. 採用した WAV と原稿・話者 ID・合成設定を保存する。修正は該当行だけ再生成し、最後に成果物を提示する。

## 読みとアクセントを調べる

スクリプトは、この `SKILL.md` のあるディレクトリからの相対パスで示す。

```sh
python3 scripts/aivis-accent-report.py 原稿.txt   # 1行1文。カナ/核 | … を表示
python3 scripts/aivis-accent-report.py -t "読ませたい一文" --speaker 888753763
```

- 製品名・複合語の意図しない句分割は、辞書登録を検討する手掛かり。複数句だから不正とは限らない。
- 漢字かな交じりの自然な原稿を基本にする。誤読した語だけ読みや表記を調整し、全体を平仮名にしない。
  画面のキャプションとは別に管理してよい。
- 英字の固有名詞も実測する。`App Store` が「アップストア」になった例があるが、読みを固定的に仮定しない。
- 名詞の列挙は読点「、」から試す。過去の環境では読点が句を分け、半角スペースが間を作る傾向があった。
  実際の句境界はクエリで、ポーズの長さは生成 WAV で確認する。

## 修正方法

必要な方法を選び、変更した文を再実測する。全方式を順番に試す必要はない。

- **辞書**（固有名詞・造語の継続利用）:
  `~/dotfiles-mac/tts/aivisspeech-dict.sh add <表記> <カナ> <アクセント核> [priority]`。
  核は「何モーラ目の直後で下がるか」で 0 は平板。一般語に負けて意図しない分割が残る場合は
  priority を上げる（最大9）。既存項目を確認してから変更し、変更後は `aivisspeech-dict.sh export` で保存する。
- **表記・言い換え**: 同音異義語や一度だけ使う原稿の誤読を局所的に直す。
- **クエリ編集**: 核の変更は `accent_phrases[].accent` を編集して `/synthesis` に渡す。
  句を分割する場合は `moras` と句構造も編集する必要があり、`accent` の変更だけでは分割されない。
- **表現**: 話者スタイルや `intonationScale`（初期候補 1.2〜1.35）を変える。
  エンジン・モデルが対応するパラメータを確認し、誤読修正とは分けて扱う。

## 動画の尺と整音

- 尺の初期見積もりは日本語約5.5文字/秒。動画では開始をシーン開始 +0.45秒、読み終わりに余裕を置く例がある。
  文字数から確定せず、生成後の長さで合わせる。
- 名前を覚えてほしい製品・サービスは締めの発話に含め、読みを先に確認する。
- 各行: 前後の無音を必要な分だけトリム → `loudnorm I=-17:TP=-1.5:LRA=9` → 48kHz。
  語頭・語尾を切らないよう、未処理音声も保存する。
- ミックスの初期候補: 声 +4〜5dB、BGM `volume=0.32`、`sidechaincompress`
  （threshold 0.02 / ratio 8 / attack 20 / release 500）、最後に `alimiter=limit=0.85`。
- 完成動画の目安は Integrated -14 LUFS / True Peak ≤ -1 dBTP。`ebur128=peak=true` などで完成品を実測する。
  声が埋もれる場合は声と BGM のバランスを調整する。配信先の正規化仕様を固定の前提にしない。

## 比較・保存

必要な場合は候補の名前と順序を添え、0.7秒の無音を挟んだ比較音声と個別音声を出力する。
出力先は作業の素材配置規約に従い、規約がなければ作業フォルダ内にまとめる。
音声の好みについてユーザーの選択が必要でも、他の発話の生成・整音は進めてよい。

```sh
ffmpeg -n -f lavfi -t 0.7 -i anullsrc=r=48000:cl=stereo -i a.wav -i b.wav \
  -filter_complex "[1:a]aformat=sample_rates=48000:channel_layouts=stereo[a];[2:a]aformat=sample_rates=48000:channel_layouts=stereo[b];[a][0:a][b]concat=n=3:v=0:a=1[out]" \
  -map "[out]" compare.m4a
```

同じ原稿でも再生成時に波形が変わり得る。採用 WAV は再生成に頼らず保管し、
`n00.wav`, `n01.wav` のように1行1ファイルにすると差し替えやすい。
録音から切り出すときは `silencedetect=n=-38dB:d=0.35` などで無音候補を検出し、発話の途中で切れていないか確認する。
