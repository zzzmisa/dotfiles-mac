# TTS ナレーション制作（AivisSpeech）

環境（インストール・辞書のバックアップ・Qwen3-TTS）は `~/dotfiles-mac/tts/README.md`。
ここは**エージェントが原稿から音声を作って直すときの手順**。前提: AivisSpeech.app が起動している
（API `http://127.0.0.1:10101`）。

## 原則: 読みは当て推量せず実測する

エージェントは音声を聴けない。誤読・アクセントの指摘に対して原稿を推測で書き換えると空振りする。
必ず `/audio_query` でカナと**アクセント句の区切り**を実測し、原因を特定してから直す。

```sh
python3 ~/.claude/skills/misa-tts-narration/scripts/aivis-accent-report.py 原稿.txt   # 1行1文。カナ/核 | … を表示
python3 ~/.claude/skills/misa-tts-narration/scripts/aivis-accent-report.py -t "読ませたい一文"
```

判定の目安（機械的に見る）:
1. **製品名・複合語が2句以上に分割されていたら欠陥** → 辞書登録で1句に結合して再実測
2. 名詞の列挙は読点「、」で句が分かれているか（半角スペースでは区切れない）
3. 文末の製品名は句末で下降して不明瞭になりがち → 読点で独立した句にすることを検討

## 原稿の作り方

- **原稿は漢字で書く**。ひらがなだと TTS が読み間違える。画面のキャプションがひらがなでも、原稿は別物として漢字で書く
  （キャプションと一字一句同じである必要はない）
- 1行の長さは**シーンの尺 − 0.5 秒**まで（読み上げは約 5.5 文字/秒。3 秒台のシーンなら日本語 16 文字、英語 6 語が目安）
- ナレーションの開始はシーン開始 **+0.45 秒**。頭から鳴らすと切り替わりと重なって聞き取りにくい
- 名前を覚えてほしいもの（製品名・サービス名）は締めの行で**声に出す**。読み方は辞書に登録しておく
- 名詞の列挙は読点「、」で区切る。「・」や半角スペースでは区切れない
- `App Store` は自動で「アップストア」と読まれる（アルファベット読みにならない）。英字の固有名詞は一度実測する

## 読点と半角スペースは役割が違う

| 記号 | アクセント句 | ポーズ（無音） | 使いどころ |
| --- | --- | --- | --- |
| 読点「、」 | **区切る**（前の句にモーラとして取り込まれ、句が分かれる） | ほぼ作らない | 名詞の列挙、複合語の誤結合を防ぐ |
| 半角スペース | 区切らない（隣接する文節が融合することがある） | **作る** | 文の意味の切れ目で間を空けたいとき |

どちらが自然かは耳でしか決まらないので、**両方を生成して聴き比べ**を用意する（下記）。

## 誤読・アクセントの直し方（効く順）

1. **辞書登録**（固有名詞・造語・複合語）: `~/dotfiles-mac/tts/aivisspeech-dict.sh add <表記> <カナ> <アクセント核> [priority]`。
   アクセント核は「何モーラ目の直後で下がるか」、0 は平板。**一般語に負けて分割される語は priority を上げる**（9 まで）。
   登録したら `aivisspeech-dict.sh export` でバックアップに書き出す
2. **表記の変更**: 同音異義の誤読（例: 「空」→ソラ／カラ）は原稿の言葉を言い換える方が確実
3. **accent_phrases の書き換え**: `/audio_query` の結果 JSON の `accent_phrases[].accent`（核）を変えて `/synthesis` に渡す。
   核だけ変えたい語（例: 平板にしたい）や、1句に融合した語を2句に分割したいときに使う
4. **合成パラメータ**: 感情を乗せたい文だけ `intonationScale`（1.2〜1.35）を上げる、話者スタイル ID を変える

## 聴き比べクリップ（良し悪しは人が決める）

音声の良し悪しはエージェントには判断できない。候補を複数作り、0.7 秒の無音を挟んで 1 ファイルに連結して
`~/Downloads/` に置き、Misa に選んでもらう（個別ファイルも並べて置くと行き来しやすい）。

```sh
ffmpeg -y -f lavfi -t 0.7 -i anullsrc=r=48000:cl=stereo -i a.wav -i b.wav \
  -filter_complex "[1:a][0:a][2:a]concat=n=3:v=0:a=1[a]" -map "[a]" compare.m4a
```

## 動画に載せる整音チェーン

```
各行: silenceremove（前後トリム）→ loudnorm I=-17:TP=-1.5:LRA=9 → 48kHz
ミックス: 声だけ +4〜5 dB → BGM volume=0.32 ＋ sidechaincompress（threshold 0.02 / ratio 8 / attack 20 / release 500）
       → alimiter=limit=0.85
目標: 完成品 Integrated ≈ -14 LUFS / True Peak ≤ -1 dBFS（ebur128 で実測して声のゲインを ±1 dB 調整）
```

全体にゲインをかけない（BGM は連続音で体感ラウドネスが高く、数値以上にうるさく感じる）。声だけを上げる。
YouTube は -14 LUFS に正規化するが、**大きい動画を下げるだけで小さい動画は上げない**。-18 LUFS で書き出すと
他の動画と並んだとき 4 dB 小さいまま再生され、-14 を超えても下げられるだけなので超える意味はない。

## TTS は再現できない

同じ原稿でも再生成すると波形が変わる。採用した wav は成果物として保管し、直すときは**その行だけ**再生成する。
1 行 1 ファイル（`n00.wav`, `n01.wav`, …）にしておくと差し替えが効く。

## 素材音声を切り出す場合

外部で録音した音声などを使うときは、無音区間から各行を自動で切り出せる。

```sh
ffmpeg -i rec.m4a -af silencedetect=n=-38dB:d=0.35 -f null - 2>&1 | grep silence_
```
