# 構成・キャプション・エンドカード

## 尺と構成の型

**20秒前後**を狙う。Shortsは60秒まで使えるが、短いほど完走率が上がる。

1. **フック**（3〜4秒）— 一番派手な・意味が分からない絵を先頭に置く。
   説明的なキャッチコピーより、具体的な現象から入る方が強い
2. **説明シーン**（3〜4秒 × 2〜3本）— 1シーン1メッセージ
3. **アプリ画面**（5〜6秒）— ホーム画面など「これがアプリです」と分かる絵
4. **エンドカード**（4秒）— アプリアイコン＋アプリ名＋App Storeバッジ＋一言

シーンの切り替えはカット、エンドカードだけ0.5秒のクロスフェードで繋ぐ。

**アプリ画面のシーンでは、アプリ自身が画面に出しているキャッチコピーを
ナレーションで読む**とキャプションを置かずに済む。キャプションを置かなければ
Shorts UIとの被りを気にする必要がなくなる。

シーンを切り出すときは**動きのある瞬間を含める**。区間の後半が静止画になっている素材は、
静止部分だけ使うと弱い。逆に長すぎるスクロール等は末尾を使う（**途中で切れて終わらない**）。

## Shorts UIのセーフエリア（実機実測）

1080×1920の動画に対して、YouTubeアプリのUIが覆う範囲。

| 領域 | 範囲 | 内容 |
| --- | --- | --- |
| 上部 | y=0〜130 | 戻る・検索・✕・⋮ |
| **下部** | **y=1540〜1920** | チャンネル行・タイトル・説明文 |
| 右 | x=850〜1080 の中央〜下 | 高く評価・コメント・共有・リミックス |

- 下端から270px空けても公開後のUIでは被る（限定公開のテストより公開後の方がUIが上まで来る）。
  **完全に干渉しないのは y<1540**
- 完全に安全な定位置は**上部 y=256**（上部UIの下端130pxから126px空く）

**ただし「被る＝ダメ」ではない。** ちびレコで上部版と下部版（下端から270px）を
両方投稿して比較したところ、**下部版の方が初速が良かった**（2026-08）。
UIに一部かかっても文字が完全に消えるわけではなく、画面の主役を隠さない利点が
上回ることがある。判断軸は次の通り。

| | 上部 y=256 | 下部（UIに一部かかる） |
| --- | --- | --- |
| 向く場面 | 映像の見せ場が画面中央〜下にある | 映像の見せ場が中央〜上にある |
| リスク | テロップが主役の絵に重なる | タイトル行にかかって読みにくくなる |

**最終的な判断は実際に投稿した数字でしかできない**。迷ったら両方ビルドして、
どちらを使うかはMisaに決めてもらう。UIとの干渉を根本的に避けたければ、
**テロップを置かずナレーションで読む**（それが可能なシーンかどうかで決まる）。
- アプリ画面のシーンでキャプションを置きたい場合は、フレームをピクセル走査して
  無地の帯を探す。アプリのタイトル文字とコンテンツの間に空きがあることが多い

```sh
# フレームを取り出して、単色の横帯（＝何も描かれていない領域）を検出する
ffmpeg -ss <t> -i in.mp4 -frames:v 1 frame.png
python3 -c "
from PIL import Image
im=Image.open('frame.png').convert('RGB'); W,H=im.size; px=im.load()
start=None
for y in range(H):
    cols=[px[x,y] for x in range(0,W,4)]
    plain = min(min(c) for c in cols)>225 and max(max(c) for c in cols)<255
    if plain and start is None: start=y
    if not plain and start is not None:
        if y-start>=40: print(f'y={start}-{y} 高さ{y-start}')
        start=None"
```

## キャプション

- **1フレーム目（t=0）から表示する**。`enable='lte(t,<終了>)'`。
  最初のフレームがサムネイルになるので、0.2秒でも空白を作らない
- 表示は「シーン開始+0.2秒 〜 シーン終了-0.1秒」。シーンをまたがせない
- 文言は**アプリ本体の表記に合わせる**（分かち書き・漢字/かなの使い分けまで）。
  幼児向けアプリならひらがな＋分かち書き、それがアプリの初回起動時の表示と一致する
- 文字数を揃えると自動縮小が効かずフォントサイズが揃う。1文だけ長いと、そこだけ小さくなる
- ffmpegに `drawtext` がないビルドなので、**PillowでPNGを作ってoverlayする**

**表記の一貫性**: 本編がひらがななのにエンドカードだけ漢字、のような混在は目につく。
ただしアプリ名は正式名称のまま使う（App Storeの検索性のため）。
漢字が避けられない場合は**ふりがな（ルビ）を振る**。ルビは本文の0.4倍サイズ。
動画のキャプション（42pt相当）ではルビは潰れて読めないので、**大きく表示される
エンドカードでだけ**使う。

## エンドカード

1080×1920のPNGを作り、動画の末尾に0.5秒クロスフェードで繋ぐ。

- 構成: 角丸加工したアプリアイコン → アプリ名 → 一言（`App Storeで さがしてね` 等）→
  App Store公式バッジ
- 配置は中央〜上寄り（Shorts UIの下2割と右端を避ける）
- 背景はアプリの背景色、文字はアプリの文字色（画面から実測した値を使う）
- App Store公式バッジの取得（SVGが返るのでPNG化する。`brew install librsvg`）:

```sh
curl -s -o badge.svg "https://toolbox.marketingtools.apple.com/api/v2/badges/download-on-the-app-store/black/<ja-jp|en-us|zh-cn>"
rsvg-convert -h 200 badge.svg -o badge.png
```

- 尺は**ナレーションの長さ+0.5秒以上**。読み上げが3.5秒なら4.0秒では足りないことがある
- エンドカードの一言は「押し売り」にしない。Shortsはループ再生されるので、
  強い売り込みは2周目に入る瞬間が不快になる。場所を伝えるだけでいい

## アプリ画面のノイズ消し

プレビュー動画を素材にする場合、焼き込み済みのキャプションや設定ボタンが邪魔になる。
**実測色の単色PNGを作ってoverlayで隠す**。

```sh
python3 -c "from PIL import Image; Image.new('RGB',(850,115),(247,245,236)).save('patch.png')"
```

ffmpegの `drawbox` はYUVのレンジ変換で色がズレる（254が234になる）ので使わない。
色はスクリーンショットからピクセル値を読んで決める。
