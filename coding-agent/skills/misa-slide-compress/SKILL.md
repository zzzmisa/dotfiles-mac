# プレゼン資料の容量削減

`.key` / `.pptx` / スライドの `.pdf` を軽量化する。既定はフルHD投影・印刷用途だが、
画質を保証するものではない。用途と原本の画質に合わせて結果を確認する。
スクリプトのパスはこの `SKILL.md` のディレクトリを基準にする。

## 進め方

1. 対象・用途・既存の変更を確認し、原本を**同期対象外のローカル領域**へバックアップする。
   `~/Desktop` は iCloud 同期される場合があるため、同期外だと仮定しない。
   一意なバックアップ先へ `ditto "$SRC" "$BACKUP"` でコピーし、原本が揃っていることを確認する。
2. 対象の形式だけ処理する。PPTX/PDF は原本から**新しい出力パス**へ書き出す。
   Keynote は作業用コピーを処理する。原本に圧縮を重ねない。
3. 容量と下記の検証結果を比較し、小さくなり、用途を満たした成果物だけ採用する。
   問題があるファイルは原本を維持し、他のファイルの処理は続ける。
4. アーカイブ用途では `touch -r "$ORIGINAL" "$OUTPUT"` で更新日時を戻す。
   完了・未処理・不採用の件数、容量差、成果物とバックアップの場所を報告する。
   バックアップの削除はこの作業に含めない。

既に承認された軽量化に追加の確認を挟む必要はない。画質・編集機能の追加の破棄は依頼の範囲に従う。

## Keynote

`scripts/keynote-reduce.sh <file.key>` は1件を GUI で処理する。
一括処理は `scripts/keynote-batch.sh <work_root> <backup_root> <log.tsv> [restart_every]`。
**標準入力に作業ルートからの相対パスを1行ずつ渡す**。バックアップも同じディレクトリ構造にする。
改行を含むファイル名とディレクトリ形式の `.key` はこのスクリプトの対象外。

事前条件:

- 実行するアプリ（Codex / Claude / ターミナル等）のアクセシビリティ権限がある。
- 画面がロックされておらず、バッチ中に別の GUI 操作をしない。
- Keynote の既存書類が0件である。利用者の書類を全閉じしたり、無応答を理由に強制終了しない。

「ファイルサイズを減らす」は画像を再圧縮する。縮小倍率やテーマ画像の対象外扱いは
過去の実測であり、現行バージョンも同じとは限らない。まず代表的な1件で結果を確認する。
バッチは失敗・容量増加時にバックアップへ戻し、mtime を復元する。単体スクリプトを使う場合は呼出側で比較・復元する。

## PowerPoint

```sh
python3 scripts/pptx-optimize.py input.pptx output.pptx --dpi 350
python3 scripts/pptx-optimize.py input.pptx --dry-run
```

Python + Pillow を使用する。対象は `.pptx`。他の OOXML 形式へそのまま流用しない。

- 使用箇所ごとの表示サイズと crop から必要画素を求め、最も厳しい条件で**縦横比を保って縮小**する。
  グループ変形や背景など表示寸法が確定しない画像は据え置く。
- 画像のパート名・拡張子を維持する。画像を拡大しない。解像度据置の JPEG は再圧縮しない。
- JPEG の ICC / Adobe 色情報は保持する。向きの EXIF を持つ画像・複数フレーム画像は再エンコードしない。
  メタデータ除去は画像の無劣化処理でも、メタデータ自体は失われる。
- 孤児メディア・サムネイルは、内部リレーションと明示的な Content Type 宣言のどちらにもない場合だけ削除する。
- `--drop-cropped` は既定 OFF。1箇所だけで使われる画像の見えない領域を物理削除する。
  **後からトリミングを広げ直せなくなるため、明示的に希望された場合だけ使う。**
- 非表示スライドの削除や PNG→JPEG 変換は行わない。

スクリプトはパート構成・画像のデコード・`[Content_Types].xml` と `.rels` の不変を検証する。
`--drop-cropped` の場合だけ対象 `srcRect` の属性を変更する。
構造チェックだけでは画質・色・crop の見え方は保証できないため、変更画像を含む代表スライドを目視比較する。

## PDF

`scripts/pdf-optimize.sh <in.pdf> <out.pdf> [dpi]`（既定300）。Ghostscript・qpdf・Poppler が必要。

| 方式 | 内容 | 主な適性 |
| --- | --- | --- |
| A | Ghostscript の画像縮小・再圧縮後に qpdf。非可逆 | 写真主体 |
| B | qpdf の Flate 再圧縮・オブジェクトストリーム化・リニアライズ。画像は再圧縮しない | スクリーンショット主体 |

A が B より10%以上小さい場合だけ A を選ぶ。フォント埋め込みは維持する。
スクリプトの選択は容量とページ数を基準にした**候補選択**であり、最終採用には次の検証が必要。
終了コードは 0=出力あり、1=失敗、2=縮まらず出力なし。

## 検証と判断

`scripts/verify.sh <backup_root> <work_root>` は PDF のページ数・抽出文字の多重集合・未埋め込みフォント、
Keynote の ZIP 整合性・開けるか・スライド数を確認し、不一致時は非ゼロで終了する。
PPTX は最適化スクリプト内の検証を使う。ツール失敗や空の検証値を一致扱いしない。

- ページ数・スライド数が変わった候補、フォント埋め込みを失った候補は採用しない。
- PDF の抽出文字差、タグ消失はコピー・検索・アクセシビリティの機能差である。
  見た目が正常でも無条件に採用せず、機能保持が必要なら B または原本を使う。
- 非可逆処理は代表ページと変更箇所を用途の解像度でレンダリングし、等倍で比較する。
  DPI は `必要な横幅px ÷ ページ幅inch` で計算する。`-r 192` が1920pxになるのは幅10inchの場合だけ。
- 画像内の文字・UIスクリーンショット・細線を優先して見る。4KではフルHD以上の解像度が必要。
