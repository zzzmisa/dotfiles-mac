# トラブルシュート

軽量化で詰まったときの症状別の対処と、運用上の落とし穴。手順そのものは SKILL.md 本体を見る。

## Keynoteの「開けませんでした」

**「開けませんでした」が連続したら、原因は次のどれか。** 全部この症状に化けるので、
1つ直して安心せずに順に潰す（実測で3つとも踏んだ）。

| 症状 | 原因と対処 |
| --- | --- |
| 全件が「開けませんでした」 / 前面に出せない | **画面がロックされている。** GUIスクリプティングはロック中に一切動かない。ウインドウをAXで取得できず、Keynoteを前面にも出せない。`ioreg -n Root -d1 -a \| grep CGSSessionScreenIsLocked` で判定し、`caffeinate -d` でディスプレイスリープを抑止して予防する（`keynote-batch.sh` が自動で行う） |
| 途中から全件が「開けませんでした」 | **ウインドウを持たない書類が溜まっている。** 縮小が途中で止まると書類だけが残り、`count of windows` は0のままなので「クリーン」と誤判定する。**必ず `count of documents` も見る**。実測で36件溜まって全滅した |
| 書類は開くのにウインドウが0のまま | **`open -b -j`（非表示起動）を使っている。** 可視で起動し、必要なら `set visible to true` してから待つ |
| メニューをclickしても無反応 | メニューを開く前の `enabled` はキャッシュで `false`。**メニューバー項目を先にclickして開き**、`enabled` が `true` になるまで待ってからclickする |
| 2件目以降が全部失敗する | エラーダイアログが1枚出ると以降の `open` が全部詰まる。**1ファイルずつ**処理し、`subrole = AXDialog` を検出したら閉じる |
| `AppleEventがタイムアウト` | AppleScript内でループを完結させない。**bash側から1ステップずつ**叩いてポーリングする。`count of documents` が**空文字**を返すのは「0件」ではなく「無応答」。取り違えるとメッセージが嘘になる |
| `ファイルを読み取れませんでした` | 多くは上記の連鎖の巻き添え。ファイル破損ではないので、状態をクリアして再実行すれば通る |

**どの失敗経路でも書類を必ず閉じること**（`trap` で `close every document saving no`）。
閉じ忘れが1件でもあると上記2つ目の症状に化ける。

## Keynoteのバッチ運用

- **Keynoteを書類なしで起動すると「開く」ダイアログが出る。** これは書類ではないので
  `documents=0 / windows=1` になり、状態チェックが永久に通らず全件が門前払いされる
  （実測: 38件が1件も処理されずに失敗）。`restart_keynote` の直後に、
  **書類0件でウインドウがある場合だけ** Escape（`key code 53`）で閉じること
- **バッチ実行中はMacに触らない。** Keynoteのウインドウを閉じたり別アプリを操作すると、
  その時間帯のファイルがまとめて `開けませんでした` で失敗する。ファイルは書き換わらないので
  無傷だが、後でリトライが要る（実測: 50件中37件が巻き添えで失敗、再実行で全て通った）
- **縮小ダイアログの「予想サイズ」は当てにならない。** 実測で予想365KBが実際1.98MBだった例がある。
  判断は必ず処理後の実サイズで行う

## スクリプトを書くときの落とし穴

- **iCloud Drive上のファイル名はNFD（濁点が分解された形）で保存されている。**
  シェルに直接書いたNFCの文字列（`パ` `ゴ` `バ` など濁点・半濁点を含むもの）は
  `grep` / `awk` / `find -name` にヒットしない。ファイル名でフィルタせず、
  `find` の出力をそのまま配列やリストファイルに流して扱うこと
- **`pdffonts` の列は可変長。** フォント名が `[none]`、型が `Type 3`（2語）になる行があり、
  `$(NF-3)` で `emb` 列を取ると `sub` 列を読んで**未埋込の誤報**を出す
  （実測: 実際は未埋込0件なのに605件と報告した）。`verify.sh` はヘッダ行の `emb` の
  桁位置で判定して回避している

## PDF方式Aの副作用

Ghostscriptを掛ける方式Aだけに出る。方式B（qpdfのみ）は可逆なので該当しない。

- **ToUnicodeマップが一部欠ける**。実測で `…` → `É`、`🐟` → `!` に化けた。
  **描画は完全に正常**で、影響はコピー・検索のみ。`verify.sh` が文字差として検出するが、
  ページ数・埋め込みフォントが一致していれば採用してよい
- タグ付きPDF（`Tagged: yes`）のタグ構造が失われる
- `Info` の作成日時がGhostscript実行時刻に書き換わる（ファイルの更新日時はWorkflowの手順6で戻す）

## 報告とバックアップ

- **完了報告は「どこまで終わったか」を明示する。** 途中経過を「完了」と読ませると、
  利用者が保険のバックアップを消してしまう
- **バックアップは検証が全部終わるまで消さない。** 原本が無いと `verify.sh` が使えず、
  「原本と一致しているか」を永久に確認できなくなる
