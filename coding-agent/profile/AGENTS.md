# エージェント向けプロファイル（Private環境・Misaの個人開発の進め方）

Private環境では、このファイルをインストーラで
`~/.claude/CLAUDE.md`（Claude Code）と `~/.codex/AGENTS.md`（Codex）に
シンボリックリンクし、全プロジェクトで常時読み込む。Office環境では
`AGENTS.office.md`を使用する。
プロジェクト固有の知識はここに書かず、各リポジトリの CLAUDE.md / AGENTS.md / docs に書くこと。

## 背景

- 本業はWebフロントエンドエンジニア
- iOS（Swift）/ Flutterは趣味で始めたばかりの新領域なので、前提の説明を少し厚めにする
- Pythonとエージェントフレームワーク（LangGraph等）も学習中の新領域なので、同様に前提の説明を少し厚めにする
- やり取りは日本語で行う

## 個人開発の方針

- 個人開発アプリは収益化が目標。バックエンドなし（完全オフライン）＋買い切りIAPが必須条件で、サーバー運用コストは持たない
- 無料枠・無料ツールを優先する

## 進め方の好み

- 途中確認を挟まず自律的に進めてよい（破壊的操作と外部への公開操作は除く）
- 動作検証はシミュレータより実機インストールを優先する
- PRのマージと、App Storeのリリース公開はMisa自身が行う。エージェントは実施しない
- App Storeの審査提出は、Misaの明示的な指示があったときだけ実施する（自律判断では実施しない）
  - その前段階（ビルド、ASCへのipaアップロード、下書きバージョンへのメタデータ流し込み）は指示がなくても実施してよい
- GitHubリポジトリの公開・非公開を推測しない。プロジェクト固有のAGENTS.mdまたはGitHub APIで確認する
- 公開リポジトリへの `git push` は、Misaが内容を確認してから自身で行う。エージェントは実施しない
- 非公開リポジトリでは、PR作成の明示的な依頼を作業ブランチの `git push` とDraft PR作成の許可として扱ってよい
- 画像ファイル（jpg / jpeg / png / heic / webp / tiff）をコミットする前に `exiftool` で位置情報（GPS EXIF）を確認し、残っていたら `exiftool -gps:all= -location:all=` で除去する（スクリーンショットも一律チェック）
- Misa自身もコードを直接編集する。コミット前に `git status` で未コミットの変更を確認し、Misaの変更をエージェントの変更と同じコミットに混ぜないこと

## モデルオーケストレーション方針（Private開発の既定）

複数フェーズ・複数ファイルにまたがる実装タスクでは、1つのモデルで全部やらず、次の分担を既定とする。

- **指揮役（このセッションの上位モデル）**: 計画立案・フェーズ分割・各フェーズの仕様書き・
  成果物のレビュー・検証・コミットを担当する。難易度が最も高いフェーズ
  （データ互換・コアロジック・アーキテクチャ変更）は指揮役が自分で実装してよい
- **作業役（Agentツールのサブエージェント。`model` パラメータで指定）**:
  - 通常の実装・リファクタ・UI構築: `model: "opus"`
  - 機械的な作業（メタデータ・ドキュメント更新・定型コピー・一括置換・テスト雛形）: `model: "sonnet"`
  - ごく単純な探索・収集・整形: `model: "haiku"`

運用ルール:
- サブエージェントには「対象ファイル・従うべきリポジトリ規約・検証手順・コミット禁止」を
  明記した自己完結の指示を渡す（サブエージェントは会話の文脈を持たないため）
- 並行実行は、触るファイルが重ならないフェーズ同士だけ。重なる場合は直列にする
- 指揮役は各フェーズの diff を必ずレビューし、検証（テスト・lint・プロジェクト固有のチェック）を
  通してからコミットする。サブエージェントの報告を鵜呑みにしない
- 迷ったら上位モデルに倒す。下位モデルへの委任は、機械的でコスト削減が明確な作業に限る

### Codex での読み替え

このファイルは Codex（`~/.codex/AGENTS.md`）にも同じ実体がリンクされている。分担の考え方と
運用ルールはそのまま適用するが、Codex には Claude Code の Agent ツール（`model` パラメータ付き
サブエージェント）がないため、実現手段だけ次のように読み替える。

- **指揮役**: 対話セッションそのもの。reasoning effort を `high` 以上にして、計画・仕様・
  レビュー・検証・コミットを担当する
- **作業役**: `codex exec -m <model> "<自己完結の指示>"` で非対話セッションに切り出す
  - 通常の実装・リファクタ・UI構築: 既定モデル（`~/.codex/config.toml` の `model`）を
    effort `medium`〜`high` で
  - 機械的な作業（メタデータ・ドキュメント更新・定型コピー・一括置換・テスト雛形）: 軽量モデル
    または effort `low`
  - モデル名は世代交代が速いので固定で覚えない。`~/.codex/models_cache.json` か `/model` で
    そのとき利用可能なものを確認してから選ぶ
- 単一セッションで済ませたい大型タスクは、委譲を自動で行う effort（`ultra`）を使う手もある。
  その場合も diff のレビューと検証は指揮役の責任として省略しない
